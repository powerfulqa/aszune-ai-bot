# Repository audit — November 2026

Audit date: 2026-11-11. Scope: architecture, dependencies, configuration, Discord integration,
Perplexity API integration, error handling, logging, security, performance, testing, documentation
and deployment.

Each finding lists where it is, what happens now, why that is a problem, the fix, and whether the
fix changes what users see or needs a configuration change. **Status** says whether the fix is in
the pull request that added this file (`audit/perplexity-api-and-code-quality`) or still open.

## Executive summary

The bot is in good shape. The service layering is respected, the Perplexity client is already
separate from Discord handling, the previous security audit (#43) holds, and the suite was green
before the audit started (196 suites, 2062 tests).

No critical issue was found. The findings that mattered most:

1. The Perplexity request used a field (`preset`) that Perplexity deprecated in October 2026.
2. Upstream API error text could be shown to Discord users.
3. Two messages from one user could run at once and scramble the conversation history.
4. `undici`, which carries the API key to Perplexity, had a high-severity advisory.
5. About 550 lines of the central Perplexity service were unreachable.

All five are fixed in the pull request, as are the two other High findings (H4 reminders lost on a
failed send, H5 dashboard restart) and the follow-ups M10–M13 and L11. The items still open are
listed with a recommended order at the end.

## Security findings

H2, M1, M8, L1, L2, L3, L8, L9, L10 above. Checked and sound: dashboard auth (`timingSafeEqual`,
read-only without a token, loopback bind), SQL (prepared statements, fixed table allowlist), no
hardcoded secrets, no key logging, `/diag` owner check, no path from model output to a privileged
action. `npm audit --omit=dev` reports 0 vulnerabilities after the bump; the remaining 29 low and
moderate advisories are all in development dependencies.

## Performance findings

M2, M3, M7, M10, M11, L17 above. Checked and sound: the Perplexity request has a 120-second abort
signal that also covers the body read; typing timers are cleared and unref'd; the throttler queue is
capped; conversation maps are pruned; process-level rejection and exception handlers exist; the
shutdown guard prevents a double shutdown.

## Maintainability findings

M6, M13, L11, L12, L14, L15, L16 above. Oversized modules remain (`web-dashboard.js` 2410 lines,
`commands/index.js` 859, `input-validator.js` 833). They should shrink by deleting dead code, not by
rewriting.
